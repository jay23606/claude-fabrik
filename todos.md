# Todos

## Version 4: Agenten in der Halle wechseln

- [x] [W-1] Bei Klick auf einen Arbeiter in der Fabrikhalle (Spec, Builder, Approver und alle Prüfer: Sicherheit, Inspector, Bediener, Designer) lässt sich dessen Modell und Effort ändern. Auswahl Modell z. B. Fable, Opus, Sonnet, Haiku; Effort z. B. niedrig bis max (nur die Stufen, die das Modell unterstützt, bzw. die Werte, die Claude Code für Agenten kennt). Die Auswahl wird unter `~/.claude/fabrik/` gespeichert und überlebt Updates. Die Arbeiter starten danach mit diesen Einstellungen (Agent-Aufruf mit Parameter `model`, Effort wie vom Agent-Werkzeug unterstützt). Fehlt eine Einstellung, gilt der Standard aus der Agent-Definition. Gelöst: Klick oder Enter/Leertaste auf jeden der sieben Arbeiter öffnet eine Einstellungskarte mit Modell (Fable, Opus, Sonnet, Haiku, Standard) und Effort (low bis max, die Werte des Agent-Werkzeugs von Claude Code, je Modell gefiltert); gespeichert in `~/.claude/fabrik/einstellungen.json` unter `arbeiter` (gemeinsames Modul `halle/arbeiter.py`), ohne eigene Wahl gilt das Frontmatter der Agent-Definition.
- [x] [W-2] In der Halle ist die Auswahl pro Arbeiter sichtbar (aktuelles Modell und Effort), und es gibt eine Rückmeldung, wenn etwas nicht gespeichert werden konnte. Bedienung mit Tastatur möglich, Ziele mind. 44 px, Kontrast nach WCAG AA. Gelöst: Am Band stehen unter jedem Arbeiter Modell und Effort, Helm und Anzug folgen der Modellfarbe; die Karte meldet Speichern und Fehler (mit Grund) in einer `role="status"`-Zeile, Bedienung über native Auswahllisten und einen Schalter mit mind. 44 px Höhe, Fokusrahmen 3 px, Textfarben mit mind. 4,5:1.
- [x] [W-3] `fabrik` bietet dafür eine Kommandozeilenentsprechung an (z. B. `fabrik arbeiter <rolle> modell <wert>` und `fabrik arbeiter <rolle> effort <wert>`), damit die Einstellung auch ohne Halle geht. Gelöst: `fabrik arbeiter <rolle> modell|effort <wert>` (auch deutsche Effort-Namen, `standard` setzt zurück), `fabrik arbeiter <rolle>` zeigt den Stand, `fabrik modelle` liefert alles als JSON; `fabrik arbeiter <ID> <rolle> start|ende` funktioniert unverändert.
- [x] [W-4] Die gewählten Einstellungen werden von der Halle und vom Orchestrator gelesen, bevor ein Arbeiter gestartet wird. Der Orchestrator gibt `model` (und Effort, soweit unterstützt) bei jedem Agent-Aufruf mit. Gelöst: Die Halle liest den Stand bei jeder Abfrage aus den Einstellungen; `SKILL.md` verlangt vor jedem Start eines Arbeiters `fabrik modelle` und die Übergabe von `model` und `effort` aus `aufruf.<rolle>` beim Agent-Aufruf.
- [x] [W-5] Plugin-Dateien bleiben frei von persönlichen Daten und KI-Zuschreibungen. Version auf 0.4.0 in `plugin.json` und `CHANGELOG.md`, Eintrag in `CHANGELOG.md`. Gelöst: Version 0.4.0 in `plugin.json`, Abschnitt 0.4.0 in `CHANGELOG.md`, README ergänzt; keine persönlichen Daten oder Zuschreibungen hinzugefügt, `claude plugin validate` läuft durch.
